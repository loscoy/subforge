# 订阅、草稿与诊断

## 日常订阅管理

订阅页可编辑来源、每源 User-Agent 与缓存有效期；普通订阅链接可逐行批量导入，手工节点在新增订阅中整段粘贴。批量导入成功的链接会从输入框移除，失败后可继续剩余部分。

修改 URL 或 User-Agent 会使旧缓存失效。上游失败、超时、超限或解析不到有效节点时保留最后有效缓存，但本次构建明确失败，不会静默返回过期缓存或不完整的多源配置。刷新写回原子比较来源全部旧字段，编辑后的来源不会被旧请求覆盖。同一存储实例最多四个抓取，同源请求合并；跨进程/Workers isolate 使用数据库占用标记，争用请求明确要求稍后重试，崩溃后的占用最多保留一分钟。

每个节点携带来源 ID，可按来源筛选、加前缀或在组中选择来源。通用 URI 与节点 JSON 在目标格式中选择；两者不包含组、规则、DNS、TUN。URI 无法无损表示某字段时拒绝导出并提示改用 JSON 或客户端格式。节点输出含连接凭据，应按订阅密钥保护。

自动地区分组同样遵守来源选择：只发现选定来源的地区，展开后的组也不会混入其它来源的同地区节点。

## Agent 与 MCP 的变更草稿

修改订阅、配置、脚本、模板及回滚的工具生成草稿，不立即修改实体。在「变更草稿」查看字段、节点及产物的组/规则/DNS/TUN 差异与静态验证结果，再由登录用户应用。模型没有应用草稿的工具。HTTP 管理界面的手工保存仍直接生效。

验证使用当前缓存，不访问模型或真实代理节点。没有缓存、脚本执行失败、目标格式不支持的语义会阻止应用；旧配置无法构建时只提供字段差异并提示产物对比缺失。模板未绑定来源时无法完整验证。应用时再次原子检查旧实体、来源和引用；过期草稿须重新生成。配置应用保留原有版本回滚，删除实体不能通过配置版本恢复。

草稿生成只刷新草稿列表。配置实际应用后，编辑器保留未保存内容；同步请求期间新增的编辑也不会被响应覆盖。出现服务端更新提示时，可先复制需要保留的内容，再确认重新加载。普通保存、回滚与分享设置按完整旧值原子写入，并发冲突明确拒绝；失败不增加版本。回滚若引用已删除来源，会列出缺失 ID 并保持当前配置；删除与恢复引用在存储写入边界互斥。

`diagnose_profile` 返回解析、逐项操作、脚本、名称处理及目标过滤的节点变化；任意脚本的内部意图不会被猜测。`explain_route` 只确定解释域名规则及兜底规则；前置规则集、IP、DNS 或客户端运行时条件无法判定时返回不确定。`patch_config` 用索引或键加预期旧值约束局部修改。上述能力来自同一工具注册表，供内嵌 Agent 和 MCP 使用。

## 目标能力

- 覆写脚本 `main(config)` 仅允许 Mihomo/Clash 目标，输入是节点配置骨架，分组与规则由脚本自行生成。
- sing-box 不把 fallback/load-balance/relay 降级成 selector，不静默丢弃不支持的规则或 Clash rule-provider；错误引用、循环分组和不可达规则明确报错。REJECT 规则使用拒绝动作，不能作为可选择的出站组成员。
- 静态验证和配置加载检查不等于真实客户端连接成功。DNS、TUN、测速、传输协议互通与实际规则集内容仍须在用户客户端验证。

## 有限 Sub-Store 节点脚本

QuickJS 在原有 `return nodes` 与 `main(config)` 外支持单个 `operator` 或 `filter` 入口：

```js
function operator(proxies) {
  return proxies.map(p => ({ ...p, name: '入口-' + p.name }))
}
```

```js
function filter(proxies) {
  return proxies.map(p => p.name.includes('香港'))
}
```

兼容子集仅提供 `name`、`server`、`port`、`type` 公共字段；前三项可改，协议类型不可改。可筛选、排序、复制已有节点，凭据、传输字段与来源保留。不可创建新节点，访问其他协议字段会明确报错。`filter` 必须返回与输入等长的布尔数组。`$arguments` 为参数，平台名固定为 `SubForge`；平台 context、ProxyUtils、require、文件系统和网络不提供。

两个运行时均支持由微任务完成的 async 脚本，但无异步宿主 API；永不完成的 Promise 会报错。此功能不是完整 Sub-Store 环境，也不导入其配置。

## 定时刷新与历史

每源「启用定时刷新」默认关闭，由产品用户显式开启。间隔为 5–10080 分钟，Node 每分钟检查，Workers 使用配置中的每 5 分钟 Cron 检查；部署或服务停止期间不执行、不补跑。连续失败次数（默认 3）和节点减少比例（默认 50%）可配置，提醒只显示在订阅页，不发送外部通知。

刷新历史保留最近 20 次尝试，记录成功/失败和节点差异；增删名称各最多 100 项，数量计数完整，不保存凭据。更换 URL/UA 后不展示旧来源历史。节点骤减但仍可解析时保存新内容并告警；零有效节点拒绝替换。配置修改历史沿用版本列表与回滚。

存储新增列由 `0007_share_disabled.sql` 和 `0008_subscription_policy.sql` 提供；Node 自动兼容旧库，D1 由既有发布流程应用迁移。本次实现不包含备份恢复、SQLite↔D1 数据迁移或旧系统配置迁移。
